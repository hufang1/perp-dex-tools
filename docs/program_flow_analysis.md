### 价差计算公式

```
开仓方向:
- Extended: 买入 (使用 ext_ask 价格)
- Lighter: 卖出 (使用 lig_bid 价格)

价差计算:
spread_abs = lig_bid - ext_ask
spread_pct = (lig_bid - ext_ask) / ext_ask

正价差 → 有套利空间 (Lighter价格 > Extended价格)
负价差 → 无套利空间 (Lighter价格 < Extended价格)
```

### 平仓条件说明

```

- Lighter 卖出 @ 3292.7
- 开仓价差 = (3292.7 - 3290.0) / 3290.0 = 0.08%

- entry_spread = 0.08% (加权平均开仓价差)
```

## 8. 发现的问题

### 问题1: 价差监控和开仓决策的时序问题

**问题描述:**
- `SpreadMonitor` 每100ms更新价差 (独立后台任务)
- `_process_idle_state()` 每秒检查一次是否开仓
- 存在时序不一致：价差更新频率 > 开仓检查频率

**当前行为:**
```
价差监控: 100ms更新一次
开仓检查: 1000ms检查一次

可能出现:
- T=0ms: 价差达到阈值，但还没到开仓检查时间
- T=500ms: 价差已经回落
- T=1000ms: 检查开仓条件，但价差已经不满足了
```

**建议修复:**
在 `_process_idle_state()` 中增加检查频率，或者在价差达到阈值时主动触发检查

---

### 问题2: OPENING_WAIT状态的仓位检查时机

**问题描述:**
当前在 OPENING_WAIT 状态中，每秒检查一次仓位，但：
1. 前2秒内即使仓位不平衡也不会处理
2. 只有超过2秒且不平衡时才会强平

**当前代码逻辑:**
```python
# spread/spread_arb_bot.py:447
if elapsed >= 2.0:
    if not ext_has_position or not lig_has_position:
        # 强平
```

**问题:**
- 如果两边都没开仓成功，要等2秒才发现
- 如果一边开仓成功，一边失败，也要等2秒才发现

**建议:**
- 立即检查，如果有一边成交，另一边没成交 → 立即强平
- 如果两边都没成交 → 取消订单，返回IDLE

---

### 问题3: wait_for_execution的等待逻辑

**问题描述:**
当前 `wait_for_execution()` 等待3秒超时，但：
1. 超时后仍然会进入 OPENING_WAIT 状态
2. 实际上订单可能已经成交了，但查询状态有延迟

**当前行为:**
```
T=0s: 发送订单
T=3s: 超时，订单状态查询返回未成交
实际: 订单可能已成交，但交易所状态更新有延迟

进入 OPENING_WAIT 后:
- 通过查询实际仓位来判断
- 这样更可靠
```

**这是正确的设计!**
通过实际仓位判断比订单状态更可靠

---

### 问题4: 平仓条件的判断公式

**问题描述:**
当前平仓条件:
```python
is_triggered = entry_spread >= current_spread + profit_target + fee_rate
```

**问题分析:**
```
假设:
- entry_spread = 0.08% (开仓时价差)
- min_profit = 0.10% (目标利润)
- fee_rate = 0.05% (手续费)
- profit_target = 0.10%

触发条件:
0.08% >= current_spread + 0.10% + 0.05%
0.08% >= current_spread + 0.15%
current_spread <= 0.08% - 0.15% = -0.07%

问题:
- 需要价差变成负数才能触发平仓
- 负价差意味着 Lighter价格 < Extended价格
- 这在实际中可能很少发生
```

**建议修复:**
平仓条件应该是判断利润是否达到目标:
```python
# 当前利润
profit = entry_spread - current_spread

# 净利润 (扣除手续费)
net_profit = profit - fee_rate

# 触发平仓: 净利润达到目标
is_triggered = net_profit >= min_profit
# 即: entry_spread - current_spread - fee_rate >= min_profit
```

---

### 问题5: 缓存价差只增不减

**问题描述:**
`ArithmeticOpenStrategy` 的缓存价差只增不减:
```python
if new_spread > old_spread:
    cached_spread = new_spread
```

**影响:**
- 第一次开仓: 价差0.08%
- 第二次开仓: 需要 0.08% + 0.05% = 0.13%
- 如果价差先扩大到0.20%，再回落到0.15%
  - 缓存价差已经更新为0.20%
  - 需要等待价差再次达到0.25%才能开仓
  - 错过了0.15%的开仓机会

**建议:**
考虑使用滑动窗口或其他策略，避免错失机会

---

### 问题6: 冷却期设置

**问题描述:**
- 失败冷却: 10秒
- 成功冷却: 3秒

**影响:**
- 成功开仓后要等3秒才能再次开仓
- 如果价差持续扩大，会错失连续加仓机会

**建议:**
考虑基于价差变化动态调整冷却期

## 总结

### 核心流程
1. **价差监控** (独立后台任务，100ms更新)
2. **开仓决策** (IDLE状态，每秒检查)
3. **执行开仓** (OPENING状态，并发Taker订单)
4. **仓位确认** (OPENING_WAIT状态，检查实际仓位)
5. **持仓监控** (HOLDING状态，等待价差收敛)
6. **执行平仓** (CLOSING状态，并发Taker订单)

### 关键问题
1. 价差更新频率 > 开仓检查频率 → 可能错失机会
2. OPENING_WAIT等待2秒才处理不平衡 → 增加风险
3. 平仓条件公式可能有误 → 难以达到平仓条件
4. 缓存价差只增不减 → 可能错失加仓机会

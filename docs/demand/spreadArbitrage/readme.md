跨平台价差套利详细设计文档1. 核心策略逻辑角色分配：Extended (Maker 挂单池)：作为价格引导方。在 Extended 账本的买一（Bid）或卖一（Ask）位置挂单。Lighter (Taker 对冲池)：作为对冲方。一旦 Extended 的 Maker 单被吃掉，立即根据成交数量在 Lighter 以市价（Taker）进行反向平仓。获利公式：$$Profit = (Price_{Sell} - Price_{Buy}) - (Fee_{Extended} + Fee_{Lighter}) - Slippage - Gas$$由于 $Fee_{Extended(Maker)} = 0$ 且 $Fee_{Lighter(Taker)} = 0$，你的理论成本仅剩下 Gas 消耗和对冲滑点。2. 系统模块设计A. 监控层 (Monitor)实时行情流：通过 WebSocket 订阅 Extended 和 Lighter 的 L1/L2 深度数据。价差计算器：计算 Extended_Bid 与 Lighter_Ask 的价差。计算 Extended_Ask 与 Lighter_Bid 的价差。B. 策略执行层 (Executor)动态挂单模块：在 Extended 上挂单。价格参考：Lighter_Price * (1 ± 配置价差率)。动态调增：如果市场波动剧烈或 Lighter 深度变薄，自动增加价差率阈值。对冲监听模块：监听 Extended 的 OrderFilled 事件（私有订单流）。一旦触发，立即向 Lighter 发送对冲指令。C. 配置中心 (Config)min_spread_rate: 最小启动价差率（如 0.05%）。max_exposure: 最大单笔持仓/对冲头寸。slippage_tolerance: Lighter 端允许的最大滑点阈值。3. 可行性分析：为什么这套体系比普通套利强？极低费率限制：普通套利通常死在 Taker 0.1% 的手续费上，而你两端的手续费接近于 0，这意味着 0.03% 的微小价差在你这里都是盈利的。风险对冲：通过先 Maker 后 Taker 的方式，你只有在 Extended 已经确认成交的情况下才会去 Lighter 对冲，避免了“两头落空”的风险（双边 Taker 容易失败）。4. 临界情况与异常处理 (Edge Cases)在实际运行中，你可能会遇到以下“坑”，必须在代码中预留逻辑：情况一：Lighter 的对冲滑点 (Slippage)风险描述：Extended 成交了 10 ETH，但此时 Lighter 深度极浅，对冲 10 ETH 会导致价格瞬间偏移 0.1%，吞掉所有利润甚至亏损。对策：深度过滤：在 Extended 挂单的规模（Size）不得超过 Lighter 最佳买卖价位可用深度的 20%-50%。分批对冲：若单量过大，程序需判断是否分小批次对冲。情况二：网络延迟与“影子单” (Latency)风险描述：Extended 成交信号传回你的服务器需要 50ms，你发单到 Lighter 需要 50ms。在这 100ms 内，Lighter 的价格可能已经跑了。对策：预判偏置：在 Extended 挂单时，多预留 0.01% 的“延迟缓冲价差”。节点优化：使用两家交易所所在链的最快私有 RPC（如 Jito on Solana 或快速的 MEV-Geth 节点）。情况三：Extended 部分成交 (Partial Fill)风险描述：你在 Extended 挂了 1 ETH，但只成交了 0.05 ETH。对策：程序必须支持按实际成交数实时对冲。不要等全额成交才对冲，否则时间差太长。情况四：Lighter 对冲失败 (Execution Failure)风险描述：Lighter 因为 Gas 不足、余额不足或链上拥堵导致对冲失败。对策：重试机制：立即尝试下一次市价对冲。断路器：如果连续三次对冲失败，立即停止 Extended 的所有挂单，进入人工干预模式，防止风险敞口无限扩大。5. 建议的下一步行动回测深度：统计 Lighter 在你目标交易对上的平均深度。如果深度只有几百美金，这个策略无法规模化。部署 Demo：先用极小金额（如 10U）进行实操，测试 Extended 的成交信号回调速度。计算 Gas 成本：在 L2 上（如 Arbitrum/Base），一次交易 Gas 可能需要 0.1-0.2U。如果你的单笔利润低于 0.5U，Gas 会吞掉大部分利润。

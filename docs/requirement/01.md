这是一份针对您特定要求的单向（Single-Leg Direction）价差收敛套利 PRD。这份文档剔除了所有代码细节，完全聚焦于业务逻辑、数学模型和风控边界。鉴于您提到 Lighter 价格长期高于 Extended，且不考虑 Gas，我们专注于**“在 Extended 低吸，在 Lighter 高抛”**这一特定路径。产品需求文档 (PRD)：Lighter-Extended 单向价差收敛套利系统1. 策略概述本系统利用 Lighter (Lig) 价格高于 Extended (Ext) 的市场常态，执行单向套利策略。开仓方向： Extended 买入 (Long) + Lighter 卖出 (Short)。平仓方向： 价差收敛时，Extended 卖出 (Close Long) + Lighter 买入 (Close Short)。核心收益来源： 开仓时的价差 ($Spread_{Open}$) 与平仓时的价差 ($Spread_{Close}$) 之间的差值。2. 费率与成本模型 (Cost Model)基于“不计算 Gas”的前提，成本仅由交易手续费构成。Lighter: Taker 0%Extended: Taker 0.025%单边开仓成本: $0\% (Lig) + 0.025\% (Ext) = 0.025\%$单边平仓成本: $0\% (Lig) + 0.025\% (Ext) = 0.025\%$完整回合总硬性成本 ($Cost_{Total}$): 0.05%3. 核心逻辑定义3.1 价格获取标准：VWAP (成交量加权平均价)严禁使用盘口最新价（Last Price）或仅使用第一档价格。必须基于目标交易数量 ($Size$) 计算深度价格。$VWAP_{Ext\_Ask}(Size)$: 在 Extended 买入 $Size$ 数量的平均成本（参考卖单盘口）。$VWAP_{Lig\_Bid}(Size)$: 在 Lighter 卖出 $Size$ 数量的平均收入（参考买单盘口）。$VWAP_{Ext\_Bid}(Size)$: 在 Extended 卖出 $Size$ 数量的平均收入（参考买单盘口）。$VWAP_{Lig\_Ask}(Size)$: 在 Lighter 买入 $Size$ 数量的平均成本（参考卖单盘口）。3.2 开仓逻辑 (Opening Position)场景描述： 当 Lighter 的卖出价显著高于 Extended 的买入价时，进场套利。开仓价差公式 ($Spread_{Open}$):计算“卖高买低”的利润空间。$$Spread_{Open} = \frac{VWAP_{Lig\_Bid} - VWAP_{Ext\_Ask}}{VWAP_{Ext\_Ask}}$$开仓触发条件:价差必须覆盖：总成本 + 滑点保护 + 最小目标净利。$$Spread_{Open} > Cost_{Total} + Slippage_{Buffer} + Min_{Profit}$$参数示例:$Cost_{Total} = 0.05\%$$Slippage_{Buffer} = 0.05\%$ (预留给网络延迟期间的盘口变动)$Min_{Profit} = 0.1\%$ (预期的纯利润)结论: 当实时价差 $> 0.2\%$ 时，触发开仓。执行动作 (原子性要求):系统必须并发发送以下指令：Extended: Taker 买入 (Buy) 目标 $Size$。Lighter: Taker 卖出 (Sell) 目标 $Size$。状态变更: 系统进入 HOLDING (持仓) 状态。3.3 平仓逻辑 (Closing Logic) —— 价差收敛核心场景描述： 持仓期间，我们需要监控两边价格是否“靠拢”。当价格靠拢（价差缩小）时，我们反向操作，兑现利润。平仓价差公式 ($Spread_{Close}$):注意：此时我们需要在 Lighter 买回，在 Extended 卖出。我们要计算这两个价格现在的差距。$$Spread_{Close} = \frac{VWAP_{Lig\_Ask} - VWAP_{Ext\_Bid}}{VWAP_{Ext\_Bid}}$$核心：为什么这叫收敛？开仓时，Lighter 比 Extended 贵很多 (比如贵 1%)。平仓时，我们希望 Lighter 不那么贵了，或者 Extended 涨上来了 (比如只贵 0.1%，甚至 Extended 比 Lighter 还贵)。只要 $Spread_{Close} < Spread_{Open}$，理论上就在盈利方向（还需扣除手续费）。平仓触发条件:当当前的平仓价差，小于（开仓价差 - 成本 - 目标利润）时。或者是更简单的逻辑：当平仓价差缩小到硬性阈值以下。$$Spread_{Close} \le Threshold_{Converge}$$$Threshold_{Converge}$ (收敛阈值) 设定逻辑:为了保证盈利，这个阈值通常设定为 0% 附近 或者 微小的正数。如果设定为 $0\%$：代表两边价格完全抹平。如果设定为 $-0.1\%$：代表 Extended 的价格反超了 Lighter（倒挂），这时候平仓利润极其丰厚。如果设定为 $0.1\%$：代表 Lighter 依然比 Extended 贵一点点，但比开仓时的差距小多了，我们可以接受平仓。判定公式 (包含成本校验):$$Spread_{Open} - Spread_{Close} > Cost_{Total} + Min_{Profit}$$(意思：开仓时的价差 减去 现在的价差，这个差值必须大于 0.05% 的手续费加上我想赚的钱)执行动作:一旦满足条件，并发执行：Extended: Taker 卖出 (Sell) 持仓 $Size$。Lighter: Taker 买入 (Buy) 持仓 $Size$。状态变更: 系统恢复 IDLE (空闲) 状态。4. 临界值与边界情况 (Edge Cases)4.1 深度与滑点保护 (Liquidity Guard)VWAP 校验:在计算价格时，如果任一 DEX 的盘口深度不足以吃下 $Size$（例如你要买 1000 个，卖盘只有 500 个），则 $Spread$ 视为无效 (NaN)，禁止开仓。最大滑点限制:实际下单时，必须附加 Limit Price (限价) 保护。Extended 买单价格 = $Ask_1 \times (1 + 0.5\%)$Lighter 卖单价格 = $Bid_1 \times (1 - 0.5\%)$目的: 防止在下单的一瞬间有人砸盘或拉盘，导致你成交在极差的价格。4.2 单边成交风险 (Execution Risk) —— 最重要的风控这是跨 DEX 套利的死穴。场景: Extended 买入成功，但 Lighter 卖出失败（余额不足、API 报错、网络超时）。后果: 你现在手里持有 Extended 的多头仓位，如果币价下跌，你将直接承担亏损（变成了炒币，而不是套利）。处理逻辑:设定超时判定时间 $T = 3秒$。如果 $T$ 秒后，另一边仍未成交。触发强平 (Rollback): 立即市价卖出 Extended 已买入的仓位。接受亏损: 哪怕此时卖出会亏损手续费和滑点，也必须平掉，以消除单边敞口。4.3 余额死锁 (Balance Deadlock)由于这是单向策略（永远是 Ext 买，Lig 卖），资金会单向流动。现象: 随着时间推移，Extended 里的 U 会用光（全是币），Lighter 里的币会卖光（全是 U）。逻辑:开仓前检查：Ext_USDT_Balance > Size * PriceANDLig_Token_Balance > Size如果不满足，系统停止运行并报警，提示用户进行资金划转（Rebalance）。4.4 异常价差熔断场景: Lighter 的价格突然比 Extended 高出 20%。这通常意味着 Lighter 发生了预言机攻击或流动性枯竭，而不是正常的套利机会。逻辑: 设置 $Max_{Spread} = 5\%$。如果计算出的价差超过此值，视为异常数据，不执行开仓。5. 逻辑流程总结表步骤检查项逻辑/公式1. 监测盘口数据获取 Ext 卖单盘口 & Lig 买单盘口2. 计算开仓价差$(Lig_{Bid} -

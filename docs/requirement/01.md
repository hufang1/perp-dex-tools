高频价差套利系统重构需求文档 (v2.0)文档目标： 解决当前系统存在的严重执行延迟（12s+）和数据过期问题，将架构从“同步轮询”升级为“异步事件驱动”，消除滑点亏损。优先级： P0 (最高紧急)1. 核心性能指标 (KPI)重构后的系统必须满足以下硬性指标，否则视为不合格：行情延迟 (Tick-to-Trade Latency): 从接收交易所 WebSocket 信号到发出下单请求，内部处理耗时需 < 10ms。执行延迟 (Execution Latency): 从发出请求到收到交易所网关确认（ACK），耗时需 < 200ms (取决于网络物理距离)。数据新鲜度 (Freshness): 下单时刻所引用的价格数据，其生成时间戳与当前时间的差值不得超过 100ms。并发能力: 双边交易所下单必须并行发出，时间差 < 5ms。2. 架构重构需求2.1 行情接入层 (Market Data Adapter)当前问题: HTTP 轮询 (Polling) 导致获取的是几秒前的快照。新需求:WebSocket 接入: 必须通过 WebSocket 长连接订阅 Extended 和 Lighter 两个交易所的 BookTicker (最优买卖盘) 或 Depth (深度) 频道。本地维护 OrderBook: 在本地内存中维护最新的盘口快照，收到推送即刻更新。数据时效性检查:每次计算价差前，检查 last_update_timestamp。如果数据超过 500ms 未更新（可能是 WS 断连），标记为 STALE，禁止开仓。2.2 交易执行层 (Execution Engine)当前问题: 串行阻塞式代码 (req_a -> wait -> req_b)，导致双边操作不同步。新需求:全异步架构 (AsyncIO): 使用 Python asyncio + aiohttp (或 ccxt.pro) 重写核心循环。并发下单: 使用 asyncio.gather 确保 Buy 和 Sell 指令在同一毫秒内从网卡发出。订单类型变更:禁用: 纯市价单 (Market Order)。启用: 激进限价单 (Marketable Limit Order) 配合 IOC (Immediate or Cancel) 策略。逻辑: 假设买一价 3000，发单价格设为 3003 (允许 0.1% 滑点)。如果市场价突然跳到 3050，IOC 订单会自动取消，而不是高位接盘。2.3 风险控制层 (Risk Management System)当前问题: 基于过期价格 (3064) 判断，实际成交在 (3126)，无滑点保护。新需求:硬性滑点阈值:配置参数 MAX_SLIPPAGE_PCT (如 0.1%)。如果 (预期成交价 - 盘口最新价) > 阈值，程序内部直接拒绝发送指令。原子性风控 (Leg Risk Guard):监控双边成交回报。如果 A 腿成交，B 腿失败/超时/被拒：立即触发 紧急平仓 (Emergency Close) 逻辑，以市价抛售 A 腿持仓，止损离场。不要等待“下一次轮询”。3. 日志与监控系统需求 (Observability)为了杜绝“盲目亏损”，日志必须包含能够复盘的所有时间节点。3.1 结构化日志字段每笔交易日志 (trade.log / operations.csv) 必须包含以下字段：字段说明示例值校验规则signal_ts信号触发时间 (策略计算完成时)10:00:00.100-data_ts_A交易所A数据生成时间10:00:00.050signal_ts -

# 项目功能分析

## 项目概述

**项目名称**: perp-dex-tools (Perpetual DEX Tools)

**项目类型**: 去中心化永续合约交易自动化工具

**主要功能**: 这是一个模块化的多交易所自动交易机器人系统,支持在多个去中心化永续合约交易所进行自动化交易,主要目的是通过高频交易获取交易量和手续费返佣。

## 核心功能

### 1. 自动化交易策略

项目实现了两种主要的交易策略:

#### 1.1 标准做市策略
- **开仓**: 在市场价格附近下限价单
- **成交监控**: 实时监控订单成交状态
- **自动平仓**: 在预设的止盈水平自动下平仓单
- **循环交易**: 不断重复开仓-平仓流程以积累交易量

#### 1.2 对冲模式 (Hedge Mode)
- **双交易所对冲**: 在主交易所下 maker 单,在 Lighter 交易所下对冲单
- **风险对冲**: 通过在两个交易所持有相反头寸降低单边市场风险
- **套利机会**: 利用两个交易所之间的价差获利
- **交易量提升**: 同时在两个交易所产生交易量

### 2. 多交易所支持

项目采用工厂模式设计,支持以下交易所:

| 交易所 | 标准模式 | 对冲模式 | Boost 模式 |
|--------|---------|---------|-----------|
| EdgeX | ✅ | ✅ | ❌ |
| Backpack | ✅ | ✅ | ✅ |
| Paradex | ✅ | ❌ | ❌ |
| Aster | ✅ | ❌ | ✅ |
| Lighter | ✅ | 对冲交易所 | ❌ |
| GRVT | ✅ | ✅ (v1/v2) | ❌ |
| Extended | ✅ | ✅ | ❌ |
| Apex | ✅ | ✅ | ❌ |
| Nado | ✅ | ✅ | ❌ |

### 3. 风险管理系统

#### 3.1 订单管理
- **最大订单数限制**: 通过 `--max-orders` 参数限制同时活跃的订单数量
- **订单间隔控制**: 通过 `--wait-time` 参数控制下单频率
- **动态冷却时间**: 根据当前活跃订单比例动态调整下单间隔

#### 3.2 网格步长控制
- **价格间距管理**: 通过 `--grid-step` 参数防止平仓订单过于密集
- **提高成交概率**: 保持平仓订单之间的合理价格距离

#### 3.3 价格控制机制
- **停止交易价格**: `--stop-price` 在价格达到指定水平时退出交易
- **暂停交易价格**: `--pause-price` 在价格达到指定水平时暂停交易,价格回落后继续

#### 3.4 仓位监控
- **实时仓位检查**: 每分钟检查一次持仓与活跃平仓单的匹配情况
- **异常检测**: 检测到仓位不匹配时自动发送警报并停止交易

### 4. WebSocket 实时监控

- **订单状态实时更新**: 通过 WebSocket 连接实时接收订单状态变化
- **异步事件处理**: 使用 asyncio 事件系统处理订单成交和取消
- **线程安全**: 确保 WebSocket 回调与主交易逻辑的线程安全交互

### 5. 日志与通知系统

#### 5.1 日志记录
- **交易日志**: CSV 格式记录所有交易详情
- **调试日志**: 带时间戳的详细活动日志
- **控制台输出**: 实时状态更新

#### 5.2 通知系统
- **Telegram 通知**: 支持通过 Telegram Bot 发送交易通知
- **Lark (飞书) 通知**: 支持通过飞书机器人发送通知
- **错误警报**: 仓位不匹配等异常情况自动发送通知

### 6. Boost 模式

专为 Aster 和 Backpack 交易所设计的高频交易模式:
- **快速开平仓**: maker 单开仓,立即用 taker 单关仓
- **高交易量**: 短时间内产生大量交易量
- **磨损成本**: 一单 maker 费用 + 一单 taker 费用 + 滑点

## 技术架构

### 核心设计模式

1. **工厂模式**: `ExchangeFactory` 动态创建不同交易所客户端
2. **抽象基类**: `BaseExchangeClient` 定义统一接口
3. **数据类**: 使用 `@dataclass` 定义配置和结果结构
4. **异步编程**: 全面使用 `async/await` 实现高效 I/O 操作

### 关键组件

```
perp-dex-tools/
├── runbot.py              # 标准模式入口
├── hedge_mode.py          # 对冲模式入口
├── trading_bot.py         # 核心交易逻辑
├── exchanges/             # 交易所客户端模块
│   ├── base.py           # 抽象基类
│   ├── factory.py        # 工厂类
│   └── [exchange].py     # 各交易所实现
├── hedge/                 # 对冲模式实现
│   └── hedge_mode_*.py   # 各交易所对冲策略
└── helpers/              # 辅助工具模块
    ├── logger.py         # 日志系统
    ├── telegram_bot.py   # Telegram 通知
    └── lark_bot.py       # 飞书通知
```

## 使用场景

### 1. 交易量积累
- 参与交易所的交易竞赛
- 获取积分奖励
- 提升账户等级

### 2. 手续费返佣
- 通过推荐链接注册获得返佣
- 高频交易积累返佣收益

### 3. 做市流动性
- 为交易所提供流动性
- 在价格波动中获取微小利润

### 4. 套利交易
- 利用对冲模式在不同交易所间进行套利
- 降低单边市场风险

## 风险提示

> [!CAUTION]
> **无止损机制**: 此策略不包含止损功能,在不利市场条件下可能面临较大损失

> [!WARNING]
> **需要理解策略**: 使用前必须充分理解脚本逻辑和风险,避免盲目使用

> [!IMPORTANT]
> **长期视角**: 策略需要长期运行,只要价格最终回到被套的高点,之前的交易量就是零磨损的

## 参数配置建议

### 保守型配置
```bash
--quantity 0.05
--wait-time 600
--max-orders 30
--take-profit 0.02
--grid-step 0.5
```

### 稳健型配置 (作者推荐)
```bash
--quantity 0.05-0.1
--wait-time 450-650
--max-orders 40-60
--take-profit 0.02
--grid-step 0.3-0.5
```

### 激进型配置
```bash
--quantity 0.1
--wait-time 300
--max-orders 50
--take-profit 0.02
--grid-step 0.1
```

## 环境要求

- **Python 版本**: 3.10 - 3.12 (推荐)
  - GRVT 要求 Python 3.10+
  - Paradex 要求 Python 3.9-3.12
  - 其他交易所要求 Python 3.8+
- **虚拟环境**: 强烈建议使用虚拟环境隔离依赖
- **网络连接**: 稳定的网络连接以维持 WebSocket 连接

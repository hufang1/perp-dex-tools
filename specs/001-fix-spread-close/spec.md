## 问题分析：当前平仓逻辑存在的致命缺陷

### 现有平仓逻辑总结

通过分析 `spread/bot.py` 和 `spread/calculator.py` 代码，当前系统有三种平仓方式：

#### 1. 机会平仓 (`_close_pair`, bot.py:640-731)

**触发条件**: 检测到反向机会时（`_find_opposite_pair`, bot.py:408-413）

**执行逻辑**:
```python
# 使用opportunity的价格进行平仓
close_order = await self.order_manager.place_spread_maker_order(
    side=close_side,
    price=opportunity['extended_price'],  # ⚠️ 问题：使用新机会的价格
    quantity=pair.extended_quantity
)
```

**致命缺陷**: `opportunity['extended_price']` 是**新开仓机会**的价格，不是当前市场价。这导致：
- 如果新机会价差不利，平仓会使用糟糕的价格
- 平仓价格与实际市场价格脱节

#### 2. 强制平仓 (`_force_close_pair`, bot.py:733-806)

**触发条件**: 持仓时间超过阈值（由 `_check_force_close` 判断，bot.py:1079-1158）

**执行逻辑**:
```python
# 使用对手价模拟市价单
if pair.extended_side == 'buy':
    close_extended_price = extended_bid  # ✅ 正确：用bid卖出
    close_lighter_price = lighter_ask   # ✅ 正确：用ask买入
```

**评价**: 价格选择正确，但触发条件过于简单，没有考虑价差是否收敛。

#### 3. 平仓触发条件 (`_check_force_close`, bot.py:1079-1158)

**当前触发条件**（按优先级）:
1. **盈利目标平仓**: PnL >= profit_target_rate (0.05%)
2. **时间小额平仓**: 持仓 > 60秒 且 PnL > 0
3. **回本止损**: 持仓 > 60秒 且 PnL < 0，等待 PnL >= 0
4. **强制平仓**: 持仓 > 70秒，无论盈亏

**问题分析**:
- ✅ 有多层平仓策略，逻辑合理
- ❌ 但没有检查**价差收敛状态**
- ❌ 在价差扩大时（应该亏损时）也会触发平仓

### 从交易日志分析的具体问题

#### 案例1: 典型的亏损平仓

```
开仓 (套利对#1):
  Extended: 买入 @ $3094.50
  Lighter: 卖出 @ $3065.96
  价差: -$28.54 (-0.9223%)

平仓 (82.8秒后):
  Extended: 卖出 @ $3092.70 (订单ID: 2009626728063356928)
  Lighter: 买入 @ $3127.21 (订单ID: 328213)
  价差: +$34.51 (+1.116%)  ⚠️ 价差扩大了！

盈亏:
  Extended: ($3092.70 - $3094.50) × 0.01 = -$0.018
  Lighter: ($3065.96 - $3127.21) × 0.01 = -$0.613
  总亏损: -$0.630 (-2.04%)
```

**问题诊断**:
1. 开仓时价差为负（Extended贵于Lighter）
2. 如果这是"做多价差"，应该期待价差向正值收敛才能盈利
3. 但平仓时价差变为更大的正值，说明价差**扩大而非收敛**
4. 结果：两个交易所都亏损

#### 案例2: Extended仓位累积问题

从日志统计：
- 开仓交易: ~40笔
- 平仓交易: ~5笔
- **结果**: Extended仓位远超Lighter仓位

**原因分析**:
1. 平仓机会触发条件过于严格（需要反向机会）
2. 市场持续单向波动时，很少出现反向机会
3. 强制平仓时间过短（70秒），在价差不利时触发平仓导致亏损
4. 亏损后策略继续开仓，累积单边仓位

### 核心问题总结

| 问题类别 | 具体问题 | 影响 |
|---------|---------|------|
| **价差方向错误** | 开仓时可能做空了应该做多的价差 | 每次价差收敛都会亏损 |
| **平仓价格错误** | `_close_pair` 使用新机会价格而非当前市价 | 平仓执行价格不利 |
| **缺乏价差收敛检查** | 平仓时不检查价差是否收敛 | 在价差扩大时平仓亏损 |
| **平仓触发机制缺陷** | 过度依赖反向机会触发平仓 | 持仓累积无法及时平仓 |
| **强制平仓时机不当** | 70秒强制平仓不考虑价差状态 | 在最差的时机平仓 |

## 解决方案

### 方案1: 修复价差计算和开仓逻辑

**问题**: 当前可能在做空应该做多的价差

**解决方案**:
1. **重新定义价差符号**: 明确价差的正负含义
   - `spread = Extended中间价 - Lighter中间价`
   - `spread > 0`: Extended贵，Lighter便宜 → 应该做空Extended，做多Lighter
   - `spread < 0`: Extended便宜，Lighter贵 → 应该做多Extended，做空Lighter

2. **修复开仓条件** (`calculator.py:62-124`):
   ```python
   # 当前逻辑（可能错误）:
   if extended_bid < lighter_ask:  # 买入机会
       spread = lighter_ask - extended_bid  # 负值！

   # 修复后逻辑:
   spread_mid = (extended_bid + extended_ask) / 2 - (lighter_bid + lighter_ask) / 2
   if abs(spread_mid) > min_spread_threshold:
       if spread_mid > 0:
           # Extended贵 → 做空价差
           return {'side': 'sell', ...}  # 卖出Extended，买入Lighter
       else:
           # Extended便宜 → 做多价差
           return {'side': 'buy', ...}   # 买入Extended，卖出Lighter
   ```

### 方案2: 修复平仓价格选择

**问题**: `_close_pair` 使用新机会价格而非当前市价

**解决方案**:
1. **移除机会平仓逻辑**: 不依赖反向机会触发平仓
2. **使用当前市价平仓**: 参考 `_force_close_pair` 的正确做法
   ```python
   # 正确的平仓价格选择
   if pair.extended_side == 'buy':
       # 做多平仓：卖出Extended（用bid），买入Lighter（用ask）
       close_extended_price = extended_bid
       close_lighter_price = lighter_ask
   else:
       # 做空平仓：买入Extended（用ask），卖出Lighter（用bid）
       close_extended_price = extended_ask
       close_lighter_price = lighter_bid
   ```

### 方案3: 增加价差收敛检查

**问题**: 平仓时不检查价差是否收敛

**解决方案**:
1. **新增价差收敛检查函数**:
   ```python
   def is_spread_converged(
       pair: SpreadPair,
       extended_bid: Decimal,
       extended_ask: Decimal,
       lighter_bid: Decimal,
       lighter_ask: Decimal
   ) -> bool:
       """检查价差是否收敛到可以盈利的水平"""
       # 计算当前价差
       current_spread = calculate_current_spread(
           pair.extended_side, extended_bid, extended_ask, lighter_bid, lighter_ask
       )
       # 计算价差变化
       spread_change = current_spread - pair.open_spread

       # 做多价差：期待价差变大（向正方向）
       if pair.extended_side == 'buy':
           return spread_change > 0  # 价差变大则盈利
       else:
           # 做空价差：期待价差变小（向负方向）
           return spread_change < 0  # 价差变小则盈利
   ```

2. **修改平仓触发条件** (`_check_force_close`):
   ```python
   # 优先级1: 价差收敛 + 盈利目标
   if is_spread_converged(pair, ...) and unrealized_pnl >= profit_target:
       return True, "价差收敛，盈利达标"

   # 优先级2: 价差收敛 + 任意盈利
   if is_spread_converged(pair, ...) and unrealized_pnl > 0:
       return True, "价差收敛，小额盈利"

   # 优先级3: 时间到 + 价差至少不扩大
   if holding_time > time_close_threshold:
       spread_change = calculate_spread_change(...)
       if spread_change >= 0:  # 价差没有继续扩大
           return True, "时间到，价差未扩大"

   # 优先级4: 强制平仓（仅限绝对必要）
   if holding_time > max_holding_time:
       if unrealized_pnl > -max_acceptable_loss:
           return True, "强制平仓，亏损在可接受范围"
       else:
           # 亏损太大，延迟平仓等待反转
           return False, None
   ```

2. **平仓时的价差对比**:

3. **平仓决策理由**:

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 修复价差方向计算逻辑 (Priority: P1)

当前系统可能在做空应该做多的价差，导致每次价差收敛时都亏损。需要：
1. 重新定义价差计算公式，确保符号正确
2. 根据价差符号决定正确的套利方向
3. 验证修复后的方向是否与实际盈利一致

**为什么这个优先级**: 如果套利方向错误，所有交易都会亏损，这是根本性问题

**独立测试**: 使用历史价格数据回测，验证修复后的方向在价差收敛时能够盈利

**接受场景**:

1. **给定** Extended中间价 $3090，Lighter中间价 $3060（价差+$30），**当** 价差>阈值，**那么** 系统识别为"做空价差"机会：卖出Extended，买入Lighter
2. **给定** Extended中间价 $3060，Lighter中间价 $3090（价差-$30），**当** 价差绝对值>阈值，**那么** 系统识别为"做多价差"机会：买入Extended，卖出Lighter
3. **给定** 持有"做多价差"头寸（开仓时价差-$30），**当** 价差变为-$10（收敛），**那么** 系统计算未实现盈亏为正（盈利）
4. **给定** 持有"做空价差"头寸（开仓时价差+$30），**当** 价差变为+$10（收敛），**那么** 系统计算未实现盈亏为正（盈利）

### User Story 2 - 修复平仓价格选择逻辑 (Priority: P1)

当前 `_close_pair` 函数使用新机会价格而非当前市价平仓，导致执行价格不利。需要：
1. 移除依赖反向机会的平仓逻辑
2. 所有平仓都使用当前订单簿的对手价
3. 确保平仓价格反映真实市场条件

**为什么这个优先级**: 平仓价格错误直接导致交易亏损

**独立测试**: 模拟不同市场条件，验证平仓价格使用的是对手价而非机会价格

**接受场景**:

1. **给定** 持有多头仓位（买入Extended），需要平仓，**当** 执行平仓，**那么** Extended使用bid价格卖出，Lighter使用ask价格买入
2. **给定** 持有空头仓位（卖出Extended），需要平仓，**当** 执行平仓，**那么** Extended使用ask价格买入，Lighter使用bid价格卖出
3. **给定** 订单簿状态为 Extended bid=$3090/ask=$3095, Lighter bid=$3060/ask=$3065，**当** 平多头仓位，**那么** 使用 $3095 (Extended bid) 和 $3065 (Lighter ask) 计算平仓盈亏

### User Story 3 - 增加价差收敛检查 (Priority: P2)

当前平仓决策不考虑价差是否收敛，导致在价差扩大时平仓亏损。需要：
1. 新增价差收敛状态检查函数
2. 优先在价差收敛时平仓获利
3. 在价差扩大时延迟平仓或设置止损

**为什么这个优先级**: 避免在不利时机平仓，减少不必要的亏损

**独立测试**: 回测验证只有在价差收敛时才触发平仓

**接受场景**:

1. **给定** 持"做多价差"头寸（开仓价差-$30），当前价差-$10（已收敛），**当** 满足其他平仓条件，**那么** 立即平仓锁定利润
2. **给定** 持"做多价差"头寸（开仓价差-$30），当前价差-$50（扩大），**当** 触发时间平仓，**那么** 检查价差状态，延迟平仓或发出警告
3. **给定** 持"做空价差"头寸（开仓价差+$30），当前价差+$50（扩大），**当** 触发时间平仓，**那么** 检查价差状态，延迟平仓或发出警告
4. **给定** 任何持仓，当前价差较开仓扩大超过1%，**当** 触发平仓，**那么** 记录警告并在trade.log中说明"在价差扩大时平仓"

### User Story 4 - 增强诊断日志 (Priority: P3)

为了持续监控和调试，需要在trade.log中记录详细的价差信息：
1. 开仓时记录价差快照和预期
2. 持仓期间记录价差变化趋势
3. 平仓时记录价差对比和决策理由

**为什么这个优先级**: 完善的日志是验证修复效果和未来优化的基础

**独立测试**: 运行策略后检查trade.log，验证所有关键信息都被记录

**接受场景**:

1. **给定** 执行开仓交易，**当** 交易完成，**那么** trade.log记录完整的价差快照（bid/ask/中间价/价差率/方向/预期）
2. **给定** 定期持仓监控触发，**当** 输出状态，**那么** trade.log记录当前价差、开仓价差、价差变化、盈亏状态
3. **给定** 执行平仓交易，**当** 交易完成，**那么** trade.log记录平仓原因、价差对比、是否收敛、盈亏分解
4. **给定** 平仓时价差处于不利状态，**当** 记录日志，**那么** 明确标注警告信息"⚠️ 价差扩大平仓"

### Edge Cases

- 当平仓时订单簿流动性不足，系统是否使用市价单或分批平仓？
- 当价差快速波动（1秒内变化>0.5%），系统如何避免频繁开平仓？
- 当持仓达到最大时间但价差极度不利（亏损>2%），系统是平仓还是继续等待？
- 当检测到价差方向错误（开仓以来持续亏损），系统是否提前止损？
- 当WebSocket数据延迟导致价差计算不准确，系统如何处理？

## Requirements *(mandatory)*

### 功能需求

#### 价差计算修复 (Critical)

- **FR-001**: 系统必须使用中间价计算价差：`spread = Extended_mid - Lighter_mid`
- **FR-002**: 系统必须根据价差符号决定套利方向：`spread > 0` → 做空价差，`spread < 0` → 做多价差
- **FR-003**: 系统必须在开仓时记录价差快照到trade.log，包括：Extended bid/ask、Lighter bid/ask、中间价差、套利方向、预期
- **FR-004**: 系统必须验证开仓后的盈亏计算与价差变化方向一致（价差收敛时应盈利）

#### 平仓逻辑修复 (Critical)

- **FR-005**: 系统必须移除依赖反向机会的平仓逻辑（`_find_opposite_pair`），改为基于时间和盈亏状态触发
- **FR-006**: 系统必须在所有平仓操作中使用当前订单簿的对手价，不使用opportunity价格
- **FR-007**: 系统必须实现价差收敛检查函数：`is_spread_converged(pair, orderbook)` 返回价差是否向有利方向变化
- **FR-008**: 系统必须修改平仓触发条件：优先在价差收敛时平仓，在价差扩大时延迟平仓或发出警告

#### 平仓触发条件优化

- **FR-009**: 系统必须实现新的平仓优先级：
  1. 价差收敛 + 盈利目标达标 → 立即平仓
  2. 价差收敛 + 任意盈利 → 立即平仓
  3. 时间到 + 价差未扩大 → 平仓
  4. 强制平仓（仅限亏损<1%）
  5. 亏损>1%时延迟平仓，等待价差收敛

- **FR-010**: 系统必须在平仓决策时记录：平仓原因、价差对比（开仓vs当前）、价差状态（收敛/扩大）、决策理由

#### 诊断日志增强

- **FR-011**: 系统必须在每次开仓时记录价差快照（包括bid/ask/中间价/价差率/方向/预期）
- **FR-012**: 系统必须在每次平仓时记录价差对比分析（开仓价差、当前价差、变化量、变化方向、是否收敛）
- **FR-013**: 系统必须在价差扩大时平仓发出警告：`⚠️ 价差扩大平仓：开仓${X} → 当前${Y} (扩大${Z})`
- **FR-014**: 系统必须定期（每30秒）记录持仓状态，包括当前价差、开仓价差、价差变化、未实现盈亏、距离平仓条件差距

#### 仓位平衡保护

- **FR-015**: 系统必须实时追踪每个套利对的两交易所仓位数量，并记录到trade.log
- **FR-016**: 系统必须检测Extended仓位累积（数量 > Lighter仓位 + 10%容差），并记录警告
- **FR-017**: 系统必须在检测到仓位失衡时暂停新开仓，优先平仓现有仓位
- **FR-018**: 系统必须实现平仓重试机制：订单未成交时重试最多3次，每次间隔递增（1s, 2s, 5s）

### 关键数据实体

- **价差快照(SpreadSnapshot)**: 包含时间戳、Extended bid/ask/中间价、Lighter bid/ask/中间价、绝对价差、价差率、价差符号、套利方向建议
- **价差变化(SpreadChange)**: 包含开仓价差、当前价差、变化量、变化率、变化方向（收敛/扩大）、是否有利于当前持仓
- **平仓决策(CloseDecision)**: 包含触发原因、价差状态、盈亏状态、决策理由、是否警告
- **仓位平衡(PositionBalance)**: 包含Extended总仓位、Lighter总仓位、差异比例、是否失衡、建议操作

## Success Criteria *(mandatory)*

### 可衡量结果

- **SC-001**: 运行策略1小时后，trade.log中每次开仓都有完整的价差快照，包括中间价、价差符号、套利方向
- **SC-002**: 所有平仓交易中，至少80%的平仓发生在价差收敛时（价差向有利方向变化），而非扩大时
- **SC-003**: 策略整体盈亏率从当前的-2%优化到+0.3%以上（扣除手续费后仍有正收益）
- **SC-004**: trade.log中包含完整的价差追踪：每次开仓记录价差快照，每次平仓记录价差对比，定期记录价差变化趋势
- **SC-005**: Extended与Lighter仓位差异<10%，且出现累积时10秒内触发警告并暂停新开仓
- **SC-006**: 每个平仓决策都有明确的理由记录，包括价差状态分析和盈利/亏损原因

### 验收测试场景

1. **价差方向验证**: 开仓时价差为-$30（做多价差），当价差变为-$10（收敛）时，未实现盈亏应为正
2. **平仓时机验证**: 持"做多价差"头寸，只有当价差向正方向变化或回到开仓附近时才触发平仓
3. **价格选择验证**: 所有平仓操作使用对手价，可通过trade.log中的bid/ask数据验证
4. **日志完整性验证**: trade.log中每笔交易都有价差快照和对比分析

### 假设与依赖

- **假设1**: 当前策略的核心问题是价差方向计算错误，而非市场环境或交易所API问题
- **假设2**: 两个交易所的订单簿数据真实反映市场价格，价差变化是真实的市场现象
- **假设3**: 理想的价差套利策略应该在价差偏离正常范围时开仓，在价差回归时平仓
- **假设4**: 万1.5的磨损是可以通过优化时机和方向选择来降低的
- **依赖**: trade.log作为主要数据源，不需要额外的数据库或监控系统

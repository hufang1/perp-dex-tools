# 功能规格说明：Lighter-Extended 单向价差收敛套利系统

**功能分支**: `002-spread-arb`
**创建日期**: 2026-01-12
**状态**: 草稿
**输入**: 用户描述：实现Lighter-Extended单向价差收敛套利系统，基于VWAP价格计算，执行开仓/平仓逻辑，包含风控机制

## 用户场景与测试

### 用户故事 1 - 自动价差监控与开仓 (优先级：P1)

系统持续监控 Lighter 和 Extended 两个交易所的价格差异，当检测到有利可图的价差时，自动执行开仓操作。

**为什么是此优先级**：这是套利策略的核心功能，没有自动监控和开仓能力，整个套利系统无法运行。

**独立测试**：可以通过模拟两个交易所的价格数据，验证系统能否正确计算价差并在满足条件时触发开仓订单。

**验收场景**：

1. **已知** Extended 买入价格为 100,000 USDT，Lighter 卖出价格为 100,500 USDT，**当** 价差达到 0.5%（高于 0.2% 阈值），**则** 系统发送开仓订单（Extended 买入 + Lighter 卖出）
2. **已知** 价差为 0.1%（低于 0.2% 阈值），**当** 系统检测到价格，**则** 不执行任何操作，继续监控
3. **已知** Extended 卖单深度不足 1000 个单位，**当** 系统尝试计算 VWAP，**则** 将价差标记为无效，禁止开仓

---

### 用户故事 2 - 持仓监控与平仓 (优先级：P2)

当系统持有仓位时，持续监控价差变化，当价差收敛时自动执行平仓操作以兑现利润。

**为什么是此优先级**：平仓是套利策略的退出机制，必须与开仓配合才能完整实现套利循环。

**独立测试**：可以通过模拟持仓状态下的价差变化，验证系统能否在价差收敛时正确触发平仓。

**验收场景**：

1. **已知** 持有开仓位（开仓价差 0.5%），当前价差收敛至 0.05%，**当** 系统检测到价差收敛，**则** 执行平仓订单（Extended 卖出 + Lighter 买入）
2. **已知** 持有开仓位，价差从 0.5% 扩大至 1%，**当** 系统检测到价差扩大，**则** 不执行平仓，继续等待收敛
3. **已知** 持有开仓位，价差收敛后利润为负（扣除手续费），**当** 系统计算利润，**则** 不执行平仓，继续等待有利时机

---

### 用户故事 3 - 风险控制与异常处理 (优先级：P3)

系统在检测到异常情况（单边成交、余额不足、极端价差）时，采取保护措施防止损失扩大。

**为什么是此优先级**：风控是保障系统安全运行的必要条件，但不影响基本套利逻辑的实现。

**独立测试**：可以通过模拟各种异常场景，验证系统能否正确识别并采取保护措施。

**验收场景**：

1. **已知** Extended 买入订单成交成功，**当** Lighter 卖出订单 3 秒后仍未成交，**则** 系统立即市价卖出 Extended 仓位以消除敞口
2. **已知** Extended USDT 余额不足以支付目标数量的买入，**当** 系统检查余额，**则** 停止运行并发出余额不足警告
3. **已知** 计算出的价差超过 5%，**当** 系统检测到异常价差，**则** 视为无效数据，不执行开仓操作

## 需求

### 功能需求

- **FR-001**: 系统 MUST 能够从 Lighter 和 Extended 两个交易所实时获取订单簿数据（WebSocket 连接）
- **FR-002**: 系统 MUST 基于目标交易数量计算 VWAP（成交量加权平均价），而非使用盘口最新价或第一档价格
- **FR-003**: 系统 MUST 计算开仓价差：`(Lighter_Bid_VWAP - Extended_Ask_VWAP) / Extended_Ask_VWAP`
- **FR-004**: 系统 MUST 在开仓价差大于 0.2% 时触发开仓（0.05% 手续费 + 0.05% 滑点保护 + 0.1% 最小利润）
- **FR-005**: 系统 MUST 在触发开仓时并发发送 Extended 买入订单和 Lighter 卖出订单（原子性要求）
- **FR-006**: 系统 MUST 能够从 Extended 买入订单的 WebSocket 更新中获取成交价格和数量
- **FR-007**: 系统 MUST 在 Extended 买入成交后立即发送 Lighter 卖出订单进行对冲
- **FR-008**: 系统 MUST 计算平仓价差：`(Lighter_Ask_VWAP - Extended_Bid_VWAP) / Extended_Bid_VWAP`
- **FR-009**: 系统 MUST 在平仓价差满足收敛条件时执行平仓（开仓价差 - 平仓价差 > 0.15%）
- **FR-010**: 系统 MUST 在平仓时并发发送 Extended 卖出订单和 Lighter 买入订单
- **FR-011**: 系统 MUST 在开仓前验证订单簿深度是否足以支持目标交易数量
- **FR-012**: 系统 MUST 在检测到单边成交风险时（3 秒超时）执行强平操作
- **FR-013**: 系统 MUST 在下单时附加限价保护（Extended 买单不超过 Ask_1 × 1.005，Lighter 卖单不低于 Bid_1 × 0.995）
- **FR-014**: 系统 MUST 在检测到极端价差（> 5%）时视为异常数据并拒绝交易
- **FR-015**: 系统 MUST 在交易前检查账户余额是否充足（Extended USDT 余额、Lighter 代币余额）
- **FR-016**: 系统 MUST 记录所有交易日志（包括时间、交易所、方向、价格、数量）
- **FR-017**: 系统 MUST 验证订单簿更新的序列完整性，检测并处理数据缺失
- **FR-018**: 系统 MUST 在订单簿数据不一致时重新获取快照

### 关键实体

- **价差 (Spread)**：表示两个交易所之间的价格差异，包含开仓价差和平仓价差
  - 开仓价差：Lighter 卖出价相对于 Extended 买入价的溢价百分比
  - 平仓价差：Lighter 买入价相对于 Extended 卖出价的溢价百分比
- **VWAP (Volume Weighted Average Price)**：基于订单簿深度计算的成交量加权平均价
  - Extended Ask VWAP：在 Extended 买入目标数量的平均成本
  - Lighter Bid VWAP：在 Lighter 卖出目标数量的平均收入
  - Extended Bid VWAP：在 Extended 卖出目标数量的平均收入
  - Lighter Ask VWAP：在 Lighter 买入目标数量的平均成本
- **持仓状态 (Position State)**：表示当前套利系统的持仓情况
  - IDLE：无持仓，等待开仓机会
  - HOLDING：持有双向仓位，等待平仓机会
- **交易数量 (Target Size)**：每次套利操作的目标交易数量（以代币计）
- **订单簿 (Order Book)**：实时维护的两个交易所的订单簿数据
  - Bids：买单深度（价格 -> 数量）
  - Asks：卖单深度（价格 -> 数量）

## 成功标准

### 可衡量结果

- **SC-001**: 系统能够在价差出现后的 100 毫秒内检测到套利机会
- **SC-002**: 开仓订单的原子性执行成功率大于 99%（两个订单都在 1 秒内成功发送）
- **SC-003**: 单边成交风险事件的强平响应时间小于 500 毫秒
- **SC-004**: 系统连续运行 24 小时无内存泄漏或连接崩溃
- **SC-005**: 每笔套利交易扣除手续费后的净利润率为正
- **SC-006**: 订单簿数据的一致性验证准确率达到 99.9%
- **SC-007**: 余额不足警告的准确率达到 100%（无不因余额不足导致的交易失败）

### 假设

- Lighter 交易所 Taker 手续费为 0%
- Extended 交易所 Taker 手续费为 0.025%
- Lighter 价格长期高于 Extended 价格（单向套利策略有效）
- 不考虑 Gas 费用（根据需求文档说明）
- 滑点保护缓冲设为 0.05%
- 最小目标利润设为 0.1%
- 单边成交超时判定时间为 3 秒
- 极端价差阈值为 5%
- 目标交易数量由用户配置，且在两个交易所的最小订单量范围内
- WebSocket 连接在异常断开后能够自动重连
- 交易所 API 的响应时间在正常网络条件下小于 500 毫秒

### 依赖

- Lighter 和 Extended 交易所的 WebSocket API 可用且稳定
- 交易账户在两个交易所都有足够的初始资金
- 系统时钟与交易所服务器时间同步
- 网络连接稳定，延迟在可接受范围内

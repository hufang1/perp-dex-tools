# Feature Specification: 优化持仓监控输出

**Feature Branch**: `001-optimize-monitor`
**Created**: 2026-01-09
**Status**: Draft
**Input**: User description: "整合一下 把所有的监控都整合到一个输出里面。然后调整一下里面的字段，新增一个当前已实现的收益（也就是ext和lighter同时平仓之后的价格）"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 整合持仓监控输出 (Priority: P1)

作为交易员，我希望在一个整合的输出中看到所有持仓的监控信息，而不是多个分散的日志条目，这样可以更快速地了解整体持仓状况。

**Why this priority**: 这是核心需求，直接影响用户体验和监控效率。当前的分散输出使得在多个持仓时难以快速获取全局视图。

**Independent Test**: 可以通过启动机器人并开多个持仓来验证，检查日志输出是否为单个整合的消息块而非多个分散条目。

**Acceptance Scenarios**:

1. **Given** 机器人有3个活跃持仓，**When** 监控循环运行，**Then** 输出应为一个整合的消息块包含所有3个持仓的信息
2. **Given** 机器人有0个活跃持仓，**When** 监控循环运行，**Then** 输出应显示"无活跃持仓"
3. **Given** 机器人有1个活跃持仓，**When** 监控循环运行，**Then** 输出应显示该持仓的信息

---

### User Story 2 - 新增当前已实现收益字段 (Priority: P2)

作为交易员，我希望在监控输出中看到如果立即平仓（使用当前对手价）能够实现的收益，这样可以做出更明智的平仓决策。

**Why this priority**: 这个信息对交易决策很重要，但优先级低于P1，因为即使没有这个字段，用户也能通过当前价格和开仓价格手动计算。

**Independent Test**: 可以通过对比计算结果验证：监控输出中的"当前已实现收益"应该等于 (Extended平仓收益 + Lighter平仓收益)。

**Acceptance Scenarios**:

1. **Given** 做多持仓（Extended买入 @ $3000, Lighter卖出 @ $2980），**When** 当前Extended价格为$3005，Lighter价格为$3010，**Then** 已实现收益应显示为-$15（Extended盈$5 - Lighter亏$20）
2. **Given** 做空持仓，**When** 计算已实现收益，**Then** 应使用正确的价格方向（做空平仓使用bid价）
3. **Given** 任何持仓，**When** 显示已实现收益，**Then** 应明确标注这是"使用对手价立即平仓"的理论收益

---

### User Story 3 - 优化字段显示 (Priority: P3)

作为交易员，我希望监控输出的字段更加清晰简洁，去除冗余信息，突出关键数据。

**Why this priority**: 这是用户体验优化，不改变功能，但能提升可读性。

**Independent Test**: 可以通过审查输出格式验证，确保字段简洁明了。

**Acceptance Scenarios**:

1. **Given** 监控输出，**When** 显示持仓信息，**Then** 每个字段应该有清晰的标签和合理的格式
2. **Given** 多个持仓，**When** 显示整合输出，**Then** 持仓之间应该有清晰的分隔

---

### Edge Cases

- 当订单簿数据缺失时如何显示价格（使用"N/A"或最后已知价格）
- 当WebSocket断开连接时如何处理监控输出
- 当持仓数量非常大（例如>10个）时如何避免输出过长
- 当持仓正在平仓过程中（is_closing=True）时如何显示

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须将所有活跃持仓的监控信息整合到单个日志输出中
- **FR-002**: 整合输出必须包含每个持仓的唯一标识符（ID）
- **FR-003**: 系统必须计算并显示"当前已实现收益"，即使用当前对手价立即平仓的理论收益
  - 对于做多持仓：Extended使用bid平仓，Lighter使用ask平仓
  - 对于做空持仓：Extended使用ask平仓，Lighter使用bid平仓
- **FR-004**: 输出必须包含以下字段：
  - 持仓ID
  - 方向（做多/做空）
  - 持仓时间和剩余时间
  - Extended仓位信息（数量、开仓价、当前价）
  - Lighter仓位信息（数量、开仓价、当前价）
  - 当前已实现收益（新增）
  - 未实现盈亏
  - 距离盈利目标差距
- **FR-005**: 当没有活跃持仓时，输出应显示简洁的"无活跃持仓"消息
- **FR-006**: 每个持仓在整合输出中必须有清晰的视觉分隔
- **FR-007**: 系统必须每5秒输出一次整合的监控信息

### Key Entities

- **持仓监控数据**: 包含持仓ID、方向、开仓价格、当前价格、数量、持仓时间、已实现收益、未实现盈亏、盈利目标差距
- **价格数据**: Extended bid/ask、Lighter bid/ask（用于计算已实现收益）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户能够在单个日志条目中查看所有持仓状态，无需滚动多条日志
- **SC-002**: 监控输出中的"当前已实现收益"与手动计算结果误差小于0.01%
- **SC-003**: 监控输出的行数在有多持仓时减少至少60%（相比当前每持仓一条日志）
- **SC-004**: 用户能够在3秒内理解所有持仓的整体状态（通过整合输出）

## Assumptions

- 当前订单簿数据（bid/ask）是准确且实时的
- WebSocket连接正常工作，价格更新及时
- 持仓数量不会超过20个（否则输出会过长，需要考虑分页或摘要）
- 使用简体中文作为输出语言（与现有代码一致）
- "当前已实现收益"使用对手价（做多用bid平仓，做空用ask平仓）进行计算
- 日志级别为INFO，确保监控输出可见

## Open Questions

无 - 所有问题已在用户输入中明确说明。

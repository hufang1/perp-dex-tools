# Feature Specification: 价差套利核心问题修复

**Feature Branch**: `009-fix-spread-loss-fees`
**Created**: 2026-01-10
**Status**: Draft
**Input**: 用户描述: "修复价差套利核心问题：1) Extended和Lighter仓位不对等 2) Maker订单实际被收取Taker手续费 3) 收益计算错误导致持续亏损"

## 问题分析摘要

基于对交易日志 `/Users/hufang/Desktop/trade.log` 的深度分析，并结合专业交易员的建议，发现了以下**致命问题**：

### 🚨 致命伤一：中间价陷阱（Mid Price Fallacy）

**现象**: 代码使用中间价计算价差，导致虚假的套利机会

**当前代码** (`calculator.py:65-74`):
```python
extended_mid = (extended_bid + extended_ask) / 2
lighter_mid = (lighter_bid + lighter_ask) / 2
spread = extended_mid - lighter_mid  # ❌ 使用中间价
```

**问题本质**:
- 中间价是"买不到也卖不出"的价格
- 当两边中间价相等时（价差=0），实际交易需要支付两边的半个点差

**实际案例**:
```
假设：
- Extended: bid=3090, ask=3092 (mid=3091, 点差0.02%)
- Lighter:  bid=3091, ask=3093 (mid=3092, 点差0.02%)

中间价计算: spread = 3091 - 3092 = -1 (看起来有机会)

实际交易（做多价差）:
- Extended买入成本 = 3092 (ask)
- Lighter卖出收入 = 3091 (bid)
- 真实价差 = 3091 - 3092 = -1 (实际亏损！)
```

**正确算法**:
- 做多价差（Extended买，Lighter卖）: `Real_Spread = Lighter_Bid - Extended_Ask`
- 做空价差（Extended卖，Lighter买）: `Real_Spread = Extended_Bid - Lighter_Ask`
- 只有当 `Real_Spread - 手续费 > 0` 时，才是真正的赚钱机会

---

### 🚨 致命伤二：Post-Only逻辑冲突

**现象**: 虽然使用`post_only=True`，但100%的maker订单被拒绝，最终全部走taker

**当前代码** (`calculator.py:103` + `bot.py:732-736`):
```python
# 做多价差时
extended_price = extended_bid  # ❌ 用买一价作为买入限价
order = place_spread_maker_order(..., post_only=True)  # ❌ 逻辑矛盾
```

**问题本质**:
1. Post-Only规定：如果订单会立即成交，交易所会拒绝
2. 但`extended_bid`（买一价）就是会立即成交的价格
3. **结果**: 交易所100%拒绝订单 → 触发TIMEOUT → 转为taker订单
4. **结论**: Maker尝试100%失败，全线被迫走taker，这就是为什么看到手续费

**正确的Maker策略**:
```python
# 做多价差（Extended买入）
price = extended_bid - 1_tick  # 挂在买一价下方，排队等待
post_only = True

# 代价: 订单不会秒成，需要等待（这就是为什么要有maker_timeout_wait）
```

### 🚨 致命伤三：负期望收益

**现象**: 即使不考虑其他成本，当前的数学期望也是负的

**当前配置**:
```
开仓阈值: 0.06% (min_spread_rate + latency_buffer)
双边手续费: 0.045% (0.0225% × 2)
双边点差: ~0.03% (每边0.015%)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
净收益: 0.06% - 0.045% - 0.03% = -0.015%
```

**结论**: 即使延迟为0，每下一单的数学期望也是亏损的！

### 问题 4: Extended和Lighter仓位严重不对等

**现象**: 日志显示"差异率: 200.00%"，仓位严重失衡

**根本原因**:
- 仓位平衡计算逻辑错误（`bot.py` 第335-349行）
- 计算方式为绝对值相加，而非相减
- 正确逻辑应该是：`Extended总仓位 - Lighter总仓位 = 0`（对冲状态下）

### 问题 5: 平仓价格选择错误

**从日志数据计算**:
- 套利对#1: 开仓价差-$27.74 (-0.8972%), 平仓价差-$2.95, 亏损-$0.6176 (-1.9975%)
- 套利对#2: 开仓价差-$27.81 (-0.8993%), 平仓价差-$2.99, 亏损-$0.6237 (-2.0169%)
- 套利对#4: 开仓价差-$28.00 (-0.9054%), 平仓价差-$3.42, 亏损-$0.6245 (-2.0195%)

**核心问题**:
1. 平仓时价差方向反转：开仓时Extended价格高于Lighter（负价差），平仓时Lighter价格大幅高于Extended
2. 平仓价格选择错误：Lighter平仓使用ask价格导致成本大幅增加
3. 当前代码在`_close_pair_with_market_price`（第1062-1069行）中，做多平仓时Lighter使用ask价格是错误的

## 盈利公式

要实现盈利，必须满足：

```
Market Spread (Real) > Extended Fee + Lighter Fee +
                       Extended Spread + Lighter Spread +
                       Slippage
```

**当前问题**: 只考虑了公式左边的第一项（使用中间价），忽略了后面所有的成本。

## Requirements *(mandatory)*

### Functional Requirements

#### 核心修复（P0优先级）

- **FR-001**: 系统必须使用对手价计算真实价差，而非中间价：
  - 做多价差：`real_spread = lighter_bid - extended_ask`
  - 做空价差：`real_spread = extended_bid - lighter_ask`
  - 只有当 `real_spread - total_fees > 0` 时才开仓

- **FR-002**: 系统必须实现正确的maker订单定价策略：
  - 做多时：`price = extended_bid - price_tick`（挂在买一价下方）
  - 做空时：`price = extended_ask + price_tick`（挂在卖一价上方）
  - 确保maker订单不会被交易所拒绝

- **FR-003**: 系统必须调整最小价差率阈值至0.1%或更高，以确保正期望收益

#### 重要修复（P1优先级）

- **FR-004**: 系统必须正确计算Extended和Lighter的总仓位差异，使用相减而非绝对值相加的方式

- **FR-005**: 系统必须在平仓时使用正确的对手价：
  - 做多平仓：Extended用bid卖出，Lighter用bid买入
  - 做空平仓：Extended用ask买入，Lighter用ask卖出

- **FR-006**: 系统必须在价差扩大时延迟平仓，等待价差收敛而非立即强制平仓

#### 辅助功能（P2-P3优先级）

- **FR-007**: 系统必须根据订单类型（maker/taker）正确计算手续费，并在收益计算中扣除

- **FR-008**: 系统必须记录每笔交易的成本明细，包括：
  - 开仓手续费类型和金额
  - 平仓手续费类型和金额
  - 点差成本
  - 滑点成本

- **FR-009**: 系统必须在统计报告中显示：
  - 总手续费支出
  - 总点差成本
  - 各成本占收益的比例
  - 净收益

- **FR-010**: 系统必须在日志中明确标注：
  - 每笔订单是maker还是taker
  - 实际费率
  - 真实价差（对手价计算）

### Key Entities

- **真实价差计算器**: 使用对手价（bid/ask）而非中间价计算价差，区分做多和做空价差
- **手续费和成本计算器**: 记录每笔交易的手续费类型（maker/taker）、费率、金额、点差成本、滑点成本
- **仓位平衡状态**: Extended总仓位、Lighter总仓位、差异（差值而非绝对值和）、差异率、失衡状态
- **交易记录**: 扩展字段包括订单类型（maker/taker）、实际手续费率、手续费金额、点差成本
- **订单定价策略**: 定义maker订单的价格偏移规则（相对订单簿价格）、taker订单的使用条件

## Assumptions

1. Extended交易所maker手续费为0%，taker手续费为0.0225%
2. Lighter交易所手续费为0%（根据配置）
3. 点差成本约为每边0.015%（基于市场观察）
4. 滑点成本约为0.01%-0.02%（基于市场深度）
5. 当前市场条件下，价差收敛时间平均需要2-5分钟

|-------|---------|---------|------|
| **实时价差（对手价）** | 计算后记录 | 日志 + 数据库 | 验证开仓逻辑正确性 |
| **价差历史分布** | 定期统计 | 数据库 | 确定最优开仓阈值 |
| **价差波动率** | 滚动计算（100期） | 内存 | 评估市场风险 |
| **价差持续时间** | 记录每次价差出现时长 | 数据库 | 优化持仓时间预期 |
| **Extended点差** | ask - bid | 日志 | 计算真实交易成本 |
| **Lighter点差** | ask - bid | 日志 | 计算真实交易成本 |
| **点差时段分布** | 按小时统计 | 数据库 | 发现最佳交易时段 |

**关键指标**:
- 真实价差 = 对手价计算（非中间价）
- 开仓成本 = Extended点差/2 + Lighter点差/2 + 手续费
- 最优开仓阈值 = P50真实价差 + 平均成本 + 安全边际

### 调优决策流程

#### 1. 确定最优开仓阈值
```
步骤1: 收集24小时真实价差数据
步骤2: 计算价差分布（P25, P50, P75, P90）
步骤3: 计算平均成本（手续费+点差+滑点）
步骤4: 最优阈值 = P75价差 + 平均成本 + 安全边际
```

#### 2. 优化Maker定价
```
步骤1: 记录当前price_tick下的拒绝率
步骤2: 如果拒绝率>30%，增加price_tick
步骤3: 如果拒绝率<10%，减少price_tick
步骤4: 目标：拒绝率10-20%
```

#### 3. 优化持仓时间
```
步骤1: 统计不同持仓时间的收益率
步骤2: 找到收益率最高的持仓时间区间
步骤3: 设置max_holding_time为该区间上限
```

#### 4. 选择最佳交易时段
```
步骤1: 按小时统计胜率和收益率
步骤2: 避开胜率<50%的时段
步骤3: 在胜率>70%的时段降低开仓阈值
```
